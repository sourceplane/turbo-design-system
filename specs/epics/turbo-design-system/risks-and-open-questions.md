# turbo-design-system — risks and open questions

| ID | Risk | State | Notes |
|---|---|---|---|
| DE-A | `baseline-v1` is not yet proven live | OPEN | Proven offline in Baseline CI: the offline bootstrap with the blueprint's own hooks, the stage lane's own steps in a staged job tree, the Storybook served by `wrangler dev` and smoke-tested with the component's own command, every route read. A console bootstrap closes it |
| DE-B | `/` is the Worker's, not the assets' | ACCEPTED | Under `html_handling: "none"` a directory's address matches no file; the Worker serves its `index.html` (`namesADirectory`). A Storybook page with a path of its own would be a 404, and Storybook has none: it keeps its pages in the query |
| DE-C | The template's current toolchain on Node 22, not its Node 26 | ACCEPTED | Storybook 10.6, React 19.3, Vite 8.3, TypeScript 7.0, tsup 9, ESLint 10: every package's `engines` admits Node 22.12+, and the runners give 22.23. The build machine for this port ran Node 26.13 (its Homebrew Node 22 was broken), so GitHub's Node 22 Baseline CI is the proof (spike: `~/orunbase/spikes/turbo-design-system.md`) |
| DE-D | pnpm 10, not the template's pnpm 12 | ACCEPTED | The composition pins pnpm 10.12.1. Upstream's lockfile installs with its first YAML document dropped. One resolution differs: eslint-plugin-storybook's `@typescript-eslint/utils` peer takes the workspace's TypeScript 7.0.2 where pnpm 12 auto-installed 6.0.3; pnpm warns of an unmet peer (`<6.1.0`), and lint passes because the plugin's rules use no type information |
| DE-E | stack-tectonic 0.19.0, not 0.20.0 | ACCEPTED | The siblings' pin; 0.20.0's lane-shared install links each job's `node_modules` out of its tree, a layout this build has not been verified in |
| DE-F | No workflow publishes the library | ACCEPTED | The template's release workflow (Changesets on every push to `main`, npm with `NPM_TOKEN`) is dropped: `ci.yml` is the only push-to-main workflow, and a product publishing `@acme/ui` would publish somebody else's scope. The Changesets config and scripts stay for publishing by hand |
| DE-G | The sidebar shows the name, not Storybook's logo | ACCEPTED | The name seam is Storybook's `brandTitle`; with it set, Storybook shows the title in place of its logo. The theme's light or dark base still follows the system preference, as Storybook's default does |
| DE-H | Storybook's build telemetry is on | ACCEPTED | As upstream ships it: `storybook build` sends Storybook's anonymous usage telemetry. `core: { disableTelemetry: true }` in `.storybook/main.ts` or `STORYBOOK_DISABLE_TELEMETRY=1` (passed through turbo) turns it off |
| DE-I | 03-docs needs PyYAML the build box lacks | RESOLVED | Born resolved: `hooks/render-deployment-docs.sh` reads `intent.yaml` with PyYAML when present and by indentation otherwise, and `testing/render.test.sh` runs it under a python3 with no third-party packages (orun-cloud#2344 fixed the 16 baselines that had it) |
